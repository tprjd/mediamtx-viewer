2. Collapse playback lifecycle

Strong ports & adapters

components/live-player.tsx · components/hls-player.tsx · components/webrtc-player.tsx · components/vidstack-player.tsx · components/*player.test.tsx

Problem
Joining, pause, progress, visibility, retry, fallback, and rendered state require reading three React modules and two parallel effect machines.
Solution
Put shared lifecycle and recovery policy inside one deep playback-run module; retain HLS, WebRTC, and Vidstack as adapters.
  • • one lifecycle test surface
  • • locality: timers live together
  • • leverage across both protocols
  • • React renders, not orchestrates

3. Deepen OBS provisioning

Problem
Session state, launcher compatibility, credential rotation, publisher eviction, and user-safe errors cross six modules and two runtimes.
Solution
Let one provisioning module own the full setup outcome while HTTP, PowerShell, and channel-key code remain adapters.
  • • one release fact
  • • one lifecycle test table
  • • locality: failures keep context
  • • transport mapping stays thin
