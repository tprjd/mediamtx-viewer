# Domain documentation

Read `CONTEXT.md` at the repo root before exploring domain behavior. Use its
canonical terms in code, issues, and documentation. Keep it as a glossary.

For Chat changes, read [Chat operations](../chat-operations.md) for delivery,
storage, author privacy, retention, and recovery rules. Read the
[rollout guide](../chat-rollout.md) before changing deployment behavior.

Keep accepted decisions and their reasons in the relevant maintained guide.
Update that guide when a decision changes. Avoid separate decision files that
repeat the same rules.

If a proposed change conflicts with a documented rule, identify the conflict
explicitly. If a domain term is missing or ambiguous, resolve its meaning before
adding it to `CONTEXT.md`.
