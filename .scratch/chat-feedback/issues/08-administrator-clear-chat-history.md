# 08: Let an administrator clear Chat message history

Status: resolved
Category: enhancement
Priority: Normal
Blocked by: none

## Request

Add an administrator option to clear Chat messages in one selected Channel. The user confirmed this scope on 2026-09-16.

## Evidence

Administrators can already clear Chat moderation records. That action does not clear Chat messages.
Chat content expires after seven days under the [retention rules](../../../docs/chat-operations.md#verify-a-restore-before-rollout). There is no administrator message-history clearing option in the inspected UI and routes.

## Accepted decisions

- Delete stored messages and retained original message content from the selected Chat room, rather than only hiding them.
- Preserve Chat restrictions and Chat moderation records. Their existing retention rules still apply.
- Keep existing backups until they expire normally. Restoring an older backup may restore cleared messages that have not expired.

The maintainer accepted these rules on 2026-09-17. [Chat operations](../../../docs/chat-operations.md#clear-one-channels-chat-history) records this exception to automatic seven-day retention.

## Proposed acceptance criteria

- The server enforces administrator authorization.
- A confirmation identifies the selected Chat room. Other Chat rooms retain their messages.
- Active clients and reloaded clients agree on the cleared history.
- Clearing has a defined boundary so new messages are handled consistently.
- Normal history loading and realtime replay cannot restore cleared messages. An explicit backup restore is the accepted exception.
- Tests cover concurrent sends, reconnects, and unauthorized requests.

## Comments

Channel scope is settled. Deletion and restore semantics remain undecided. Do not treat clearing Chat moderation records as the requested feature.

## Agent Brief

Category: enhancement

Summary: Let an administrator clear stored Chat messages in one selected Channel.

### Current behavior

`clearChatModerationRecords` deletes moderation records, not messages.
Message history supports reading and sending but has no administrator clear action.
The retention job deletes expired message rows and queued events after seven days.
Restore replaces the Chat database, purges expired content, clears realtime recovery
history, and reconnects clients. It can restore recent messages from an older backup.

The review covered the Chat UI, message and administrator routes, retention,
outbox dispatch, and restore. No equivalent feature or prior rejection was found.
These findings come from code inspection; no destructive runtime action was run.

### Desired behavior

Provide an administrator-only Clear Chat history action for one selected Chat room.
Require confirmation that names the Channel and explains that stored messages will
be deleted. Explain that existing backups can still contain those messages and an
older backup can restore them.

Use one authoritative clearing boundary within the room's message order. Remove
messages accepted before that boundary, including retained originals of removed
messages. Preserve messages accepted after it. Keep the Chat room, participant tags,
and sequence continuity so clearing does not reset identities or restrictions.

Remove queued message content for cleared messages and invalidate realtime recovery
content. Account for events already being published and history responses already
in flight. Connected clients discard cleared rows; reloaded and reconnected clients
receive the same result. Existing backup files expire under the normal policy.

Preserve restrictions and moderation records, including their existing private-note
retention policy. References to cleared messages must tolerate missing content.
Clearing does not promise forensic erasure of filesystem copies or backups.

### Key interfaces

- Administrator authorization and confirmation: enforce permissions on the server.
- `ChatSettings` and existing administrator controls: expose the selected-room action using existing UI patterns.
- Chat history responses and `ChatTranscript`: communicate and apply the clearing boundary.
- `sendChatMessage`, `chat_outbox`, and `dispatchNextChatOutboxEvent`: coordinate sends and pending publications with clearing.
- `clearChatRecoveryHistory` and reconnect reconciliation: prevent replay of cleared messages.
- Chat restore: retain the accepted backup exception and the existing expiry purge.

### Acceptance criteria

- [x] An administrator can confirm clearing one named Channel; cancel changes nothing.
- [x] Unauthenticated, inactive, and non-administrator accounts cannot clear history, including a Channel owner without administrator status.
- [x] The selected room's earlier messages and retained original message content are absent from live storage and normal history responses.
- [x] Other rooms, participant tags, restrictions, and existing moderation records remain intact.
- [x] Concurrent sends have a consistent boundary: earlier accepted messages are cleared and later accepted messages remain.
- [x] Retrying a previously accepted, cleared send does not recreate that message. A new send remains possible.
- [x] Connected, reloaded, and reconnected clients agree after clearing; delayed responses and queued or in-flight events cannot reinsert earlier messages.
- [x] Realtime failures have a recoverable outcome and do not produce a false success that permits cleared content to return.
- [x] Empty-room clearing is safe, and message references in moderation views handle deleted content.
- [x] Tests cover permissions, room isolation, send and clear races, retry behavior, and client reconciliation.
- [x] Backup and restore documentation states that older backups may restore cleared messages; expired content still gets purged after restore.

### Out of scope

Clearing all Channels at once, granting this action to Channel owners, lifting
restrictions, clearing moderation records, rewriting existing backups, and
preventing intentional backup restoration of otherwise unexpired messages.

## Implementation — 2026-09-17

Added the administrator-only selected-room action with a Radix confirmation dialog.
Migration 007 stores a clearing boundary and content-free submission receipts.
Clearing deletes messages and queued payloads in one transaction. The outbox retries
recovery-history invalidation before it publishes the clear event and newer messages.
Clients filter stale responses and replay against the boundary within each restore
generation. Restrictions, moderation records, tags, and normal backup expiry remain.
