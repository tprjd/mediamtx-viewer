# 03: Remove only the selected Chat message when applying a timeout

Status: resolved
Category: enhancement
Priority: High
Blocked by: none

## Request

A Chat timeout must remove only the selected Chat message. Other messages from the participant must remain visible.

## Evidence

The shared restriction function selects all unremoved messages from the target in the previous ten minutes. It removes those messages for both timeouts and bans.
The original timeout issue explicitly required that behavior.

## Proposed acceptance criteria

- A timeout removes the selected retained message, including when it is more than ten minutes old.
- Other messages from that participant remain visible in live delivery and after reload.
- The restriction, selected Message removal, Chat moderation record, and delivery events commit atomically.
- Repeated removal does not duplicate the removal event.
- Timeout duration, expiry, and sending restrictions retain their behavior.
- Tests include multiple recent messages and an older selected message.

## Scope

This request specifies timeout behavior. Keep ban removal behavior unchanged unless the user extends the request.
Read the original Chat spec when updating the policy so the implementation contract stays consistent.

## Agent Brief

**Category:** enhancement

**Summary:** Applying a Chat timeout removes only the selected retained Chat message.

**Current behavior:**

`applyChatTimeout` and `applyChatBan` share a transaction that removes the target participant's unremoved messages from the previous ten minutes.
A selected message older than that window remains visible even though the timeout takes effect.
The timeout dialog and original policy describe removal of the previous ten minutes of messages.

**Desired behavior:**

For a Chat timeout, replace only the selected message with a tombstone. This includes selected messages older than ten minutes within the existing retention period.
Keep every other message unchanged, including recent messages from the same participant.
If the selected message is already removed, apply the timeout under the existing restriction rules without another removal record or event.
Repeated timeout requests retain their existing restriction behavior; this issue requires deduplication of Message removal, not of timeout commands.

Commit the timeout, selected Message removal, moderation records, and delivery events atomically.
Preserve the existing duration presets, expiry, private restriction feedback, and sending enforcement.
Preserve administrator protection and the current Channel owner's protection in their own room.
Chat bans continue to remove the target's messages from the previous ten minutes.
Update the timeout dialog and policy documentation to distinguish these behaviors.

**Key interfaces:**

- `applyChatTimeout` and `applyChatRestriction`: select only the target message for timeout removal within the existing transaction.
- `applyChatBan`: retain its existing removal window and restriction behavior.
- `removeChatMessage`: retain tombstones, removal deduplication, moderation records, and delivery behavior.
- `ChatMessageActions`: describe selected-message-only removal for timeouts while preserving the ban description.
- `loadLatestChatHistory`, `loadChatMessagesAfter`, and the Chat outbox: keep unrelated messages visible after reload and during live delivery.
- The Chat policy and original timeout specification: record that this accepted policy supersedes the previous ten-minute timeout removal rule.

**Acceptance criteria:**

- [x] A timeout targeting one of several recent messages removes only the selected message.
- [x] A timeout targeting a retained message older than ten minutes removes that selected message and leaves recent messages unchanged.
- [x] The timeout response contains only the selected message's tombstone. History and live delivery preserve other messages.
- [x] Timing out an already removed message does not create another removal record, revision, or public removal event.
- [x] A failure to store any required moderation record or delivery event rolls back the timeout and selected removal together.
- [x] All three duration presets, expiry, sending enforcement, and private restriction notifications retain their existing behavior.
- [x] Existing moderator authorization, administrator protection, current-owner protection, and retention limits remain enforced.
- [x] Chat bans still remove the target's unremoved messages from the previous ten minutes and leave older messages unchanged.
- [x] The timeout dialog describes removal of only the selected message. The ban dialog continues to describe its ten-minute removal window.
- [x] Policy documentation and tests reflect the new timeout rule. Tests cover recent and older selected messages, repeated removal, rollback, live delivery, reload, and unchanged ban behavior.

**Out of scope:**

- Changing Chat ban removal, timeout presets, reversal rules, or authorization.
- Restoring messages removed by earlier timeouts or altering existing restrictions.
- Changing retention, viewing or publishing permissions, or moderation history clearing.
- Adding a removal-scope setting or a new moderation action.
