# 09: Integrate the theater Chat button with player controls

Status: resolved
Category: bug
Priority: Normal
Blocked by: none

## Request

In theater mode, the Open chat control overlaps the playback mode control. It stays visible when player controls hide.
Use only the Chat icon as its visible content.

## Evidence

`TheaterChatRestore` renders an absolutely positioned button at the top right, outside `Controls.Root`.
It includes visible Open chat text. Its CSS has no player-control visibility condition.
The overlap still needs browser verification at the affected viewport.

## Proposed acceptance criteria

- The closed-Chat button shows only its icon and retains an accessible Open Chat name.
- The button does not overlap the playback mode control at supported desktop and mobile widths.
- Visibility follows the player controls, including pointer, touch, and keyboard use.
- Keyboard focus makes the control available.
- Opening Chat restores the existing focus behavior.
- Closing Chat and leaving theater mode preserve the saved Chat preference.

## Scope

Change presentation and control visibility. Playback mode selection and transport behavior remain unchanged.

## Comments

Recommended outcome: ready-for-agent after browser reproduction.
Key interfaces: `TheaterChatRestore`, `PlayerTheaterProps`, and the player control group.

## Agent Brief

**Category:** bug
**Summary:** Make the closed-Chat control part of the theater player controls,
with an icon-only appearance and the same visibility behavior.

### Current behavior

`TheaterChatRestore` is a separate top-right overlay. It overlaps the playback
status badge, displays Open chat text, and stays visible after the player
controls hide. The shared player serves both HLS and WebRTC. Closing Chat in
theater mode moves focus to the restore button; opening Chat restores the
existing Chat focus behavior.

### Desired behavior

When theater mode is active and Chat is closed, show an icon-only Open Chat
button with the player controls. Use the player's existing visibility behavior
for pointer, touch, and keyboard input. Keep the control available while it has
keyboard focus. Give it an accessible Open Chat name and a visible focus indicator.

The control must not cover the playback status badge or other player controls.
Keep existing Chat open/close actions and focus transfer. Preserve the saved
Chat preference when leaving theater mode. The change must not restart playback
or alter playback mode selection.

### Key interfaces

- `PlayerControls` and `TheaterChatRestore`: share player-control layout and visibility.
- `PlayerTheaterProps`: retain `onOpenChat`, `chatOpen`, and the restore-button focus reference.
- `ChannelViewer`: preserve Chat preference and existing focus transfer.
- `VidstackPlayer`: apply the same control behavior for HLS and WebRTC.

### Acceptance criteria

- [x] In theater mode with Chat closed, the Open Chat button shows only its icon and has the accessible name Open Chat.
- [x] The button does not overlap the playback status badge or other controls at desktop and narrow widths, including 1440px, 390px, and the supported 320px minimum.
- [x] The button follows the existing player-control show/hide behavior during pointer and touch use; it does not remain visible after those controls hide.
- [x] Keyboard navigation exposes the control, shows its focus indicator, and permits opening Chat with Enter or Space.
- [x] Closing Chat transfers focus to the restore control; opening Chat preserves the existing focus destination for live Chat and the placeholder.
- [x] The restore button is absent when Chat is open or theater mode is inactive.
- [x] Leaving theater mode preserves the saved Chat preference and existing layout behavior.
- [x] Opening and closing Chat does not restart playback or change the selected playback mode.
- [x] The shared behavior applies to HLS and WebRTC, with browser checks for overlap, idle visibility, touch, and keyboard access.

### Out of scope

Playback mode policies, transport recovery, fullscreen redesign, Chat delivery,
moderation, and changes to the saved Chat preference policy.
