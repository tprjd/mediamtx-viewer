## Resolution, 2026-09-17

Closed as `wontfix` because the requested protection is already implemented. The maintainer accepted this recommendation.
No successful unauthorized ban was established. This resolution confirms the existing rule, not a reproduced incident in the deployed application.

- `mayRemoveMessage` and `applyChatRestriction` in [Chat moderation](../../../lib/chat-moderation.ts) reject an administrator target when the actor has only Channel-owner authority.
- `getChatMessageActions` uses the same authorization. [Chat message rendering](../../../components/chat-message.tsx) also hides actions on visible administrator messages from Channel owners.
- `getChatModeratorRole` gives administrator authority to an account that also owns a Channel. That account can restrict another administrator unless the target owns the current Chat room.
- The [moderation integration tests](../../../lib/chat-moderation.integration.test.ts) cover rejected owner-to-administrator bans, administrator-to-administrator bans, and protected current owners.

Verification at commit `76bb4dc`:

passed 13 tests, with 41 unrelated tests skipped.

No application change is needed. No `.out-of-scope/` entry was created because this is implemented behavior, not a rejected feature.
